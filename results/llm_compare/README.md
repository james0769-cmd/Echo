# 整理模型对照：DeepSeek (deepseek-flash) vs Kimi (kimi-k3.1-pro)

- 数据：test clip06–10，标准事实表 `facts/facts_all.csv`，计分条目 21 条（不含信息类），其中决定+共识+待办 12 条；类型口径见 `scripts/facts.py`。转写和提示词都不变，只换整理用的模型。
- 生成：`.venv/bin/python scripts/run_minutes.py --method {segmented,baseline} --source {asr,ref} --split test --model kimi-k3.1-pro`，输出到 `results/minutes/*_kimi-k3.1-pro/`。
- 评测：`.venv/bin/python scripts/eval_minutes.py <runs> --split test --out results/llm_compare`。对齐模型仍用 deepseek-flash，和 DeepSeek 那几组保持一致。明细见同目录 json；DeepSeek 的数字取自 `results/eval/*_test.json`。
- 注意：Kimi K3 系列接口只接受 temperature=1（DeepSeek 用 0），所以 Kimi 的结果每次可能不同，表中是**单次运行**；重跑会读 `data/cache/llm` 缓存，数字不变。

## 观察

1. **Kimi 更保守**：每组少出 4–11 条，精确率普遍更高（直接摘要+ASR 转写精确率 1.0），召回率低 0–0.05（分段两组各低 0.05，直接摘要+人工转写两者都是 0.81）。未对上的预测（疑似虚构）也更少。
2. **分段+证据绑定的优势两种模型都成立**：直接摘要有 5–6 条没给时间段（DS+人工转写例外，只有 1 条），对上条目含原话多在 0.71–0.77；分段方案在 0.94–1.0。
3. **虚构负责人/截止都很少**（每组 0–1 条），而且只剩同一条难例：`clip08-f10`「提前了解员工医保报销是否需要经过公司」，标准里负责人未指定，DS 直接摘要+ASR 和 Kimi 两组 ASR 输入都填了"说话人自述"。
   新事实表把「到时候」「稍后」「下周」这类原话照录为截止说明（如 `clip10-f11` 标为"未定（'到时候'）"），所以纪要照抄"到时候，具体日期未知"不再算虚构；旧表下这正是虚构截止的主要来源。
4. **ASR 错误对两种模型的影响方向一致**：从人工转写换成 ASR 转写，分段方案 Kimi 召回 0.857→0.81，DeepSeek 0.905→0.857。
5. **成本**：tokens 差不多，但 Kimi 生成慢 3.5–6 倍；单次运行、计分样本只有 21 条（重要条目 12 条），±1 条就是 0.05–0.08，差距不应过度解读。

## 结论

想要"少而准"时可以用 Kimi，尤其是直接摘要；按任务要求更看重召回、并希望每条都能回到原话核对时，"分段+DeepSeek"更合适，速度也快得多。项目默认仍用 deepseek-flash，`--model kimi-k3.1-pro` 可随时切换复现。
