# 识别误差传播分析

问题：纪要里的错误，有多少是语音识别（ASR）带进来的，有多少是大模型整理时产生的？

## 方法

同一方案、同一模型（DeepSeek）、同一 prompt，只换输入：

- **A 组**：FunASR Paraformer 原始转写（`--source asr`）
- **B 组**：AliMeeting 人工转写（`--source ref`），相当于"人工修正后的转写"

两组都用 `eval_minutes.py` 对照人工事实表 `facts/fact_table.json` 评测。`scripts/error_attribution.py` 逐条比较每条标准条目在 A、B 两组里是否被纪要覆盖，按下表归因（不调用任何 API，只读已有评测结果）：

| A（ASR） | B（ref） | 归因 |
|---|---|---|
| 对上 | 对上 | 正确 |
| 漏掉 | 对上 | **ASR 导致**：识别错误传给了大模型 |
| 漏掉 | 漏掉 | **大模型导致**：输入正确也没整理出来（也可能是标注口径问题） |
| 对上 | 漏掉 | **大模型不稳定**：输入更差反而对上，差异来自模型波动 |

另给出"局部 CER"：标准原话时间段 ±0.5 s 内，ref 句与 ASR 句的字错误率。注意它受两边时间戳偏移和多人交叠影响，数值普遍偏高，只适合做相对比较。

复现：

```bash
.venv/bin/python scripts/error_attribution.py --split all
```

明细：`all.csv` / `test.csv`（每条标准条目一行，含 A、B 两组的预测内容和类型），汇总：`summary_all.md` / `summary_test.md`。

## 结果

全部 10 段，57 条标准条目（不含 rejected）：

| 归因 | segmented | baseline |
|---|---|---|
| 正确 | 47 | 40 |
| ASR 导致 | 3 | 3 |
| 大模型导致 | 5 | 10 |
| 大模型不稳定 | 2 | 4 |

只看测试集（clip06–10，30 条）：

| 归因 | segmented | baseline |
|---|---|---|
| 正确 | 23 | 20 |
| ASR 导致 | 2 | 1 |
| 大模型导致 | 5 | 7 |
| 大模型不稳定 | 0 | 2 |

## 结论

1. **大模型整理是主要误差来源，ASR 是次要来源。** 两种方案里，"大模型导致"都多于"ASR 导致"（segmented 5 : 3，baseline 10 : 3）。CER 22% 左右的转写，大部分事实仍能被正确整理出来。
2. **分段+证据绑定（segmented）主要减少的是大模型错误**：大模型导致的遗漏从 10 条降到 5 条，不稳定从 4 条降到 2 条；ASR 导致的条数两种方案一样（3 条），说明这部分误差方案本身无法消除，只能靠更好的 ASR 或人工回听。
3. **"ASR 导致"的 3 条（segmented）都不是简单的错别字**，而是识别带来的**断句和时间错位**：
   - `clip01-f03`、`clip07-f06`：ASR 把一句话切成几个碎片（如「十八到五，/岁之间这个色彩，/颜色。」「学历大 / 概在大专或及以上」），大模型把它和相邻条目合并成了一条（例如 clip07 的 m05「招聘四个岗位，学历要求为大专及以上」）。内容其实写进了纪要，但评测按一对一配对，合并后的条目只能配一个标准条目，另一条就记为遗漏。
   - `clip09-f04`：ASR 在这一段的时间戳比人工标注早几秒，同一时间窗里的文字对不上（局部 CER 0.92），原话「还需要有些活动的安排」在 ASR 里落到了别的句子附近，纪要只写了笼统的「需要说明活动的具体规划」。
   - 它们的局部 CER（平均 0.91）明显高于"正确"条目（0.46），说明归因方向可信。
4. **"大模型导致"多数和标注口径有关**：clip06 的 3 条都是"待确认"类的观点讨论，A、B 两组都输出了 0 条，模型认为这段没有决定或待办；`clip08-f02`（「已交资料二十七八人，预计招四十人」）ASR 数字完全正确，两组都没写进纪要，是纯粹的整理遗漏。
5. **类型判断几乎不受 ASR 影响**：两组都对上的 47 条里，类型「A 错 B 对」5 条、「A 对 B 错」7 条，两个方向差不多，属于模型自身的波动，不是识别误差造成的。

## 数字转写错误的处理过程（clip01，「十八到五十岁」）

**1. 原话**（人工转写 142.72–150.87 s，事实表已经过音频复核）：

> 那咱们这个，后续再定一下这个就是**十八到五十岁**之间的色彩颜色啊，咱们到时候确认一下这个颜色好吧。

**2. ASR 识别错误**：Paraformer 把「五十」识别成「五」，并把一句话切成三段（Whisper-small 也错成「18到5岁」，见 `results/asr_compare/README.md`）：

```
136.97-139.51  咱们这个后续再定一下这个就是十八到五，
139.51-140.94  岁之间这个色彩，
141.84-142.88  颜色。
```

"18 到 5 岁"在事实上不可能成立，但大模型没有办法知道原话是"五十"。

**3. 传到纪要后的结果**（四组输出）：

| 组 | 纪要条目 | 证据时间段 | 数字 |
|---|---|---|---|
| segmented + ref | 「十八到五十岁之间的色彩颜色后续再确认」（待确认，截止"后续，具体日期未知"） | 142.72–150.87 | 正确 |
| baseline + ref | 「十八到五十岁之间的色彩颜色后续再定并确认」 | 142.72–150.87 | 正确 |
| segmented + asr | 「主推年轻化机型，目标年龄区间和颜色后续再定」（和"主推年轻化"合并成一条） | 127.40–150.96 | **模型没有写数字** |
| baseline + asr | 「目标年龄区间和色彩颜色后续再确定」，引文里保留了「十八到五岁之间」 | 142.88–150.96 | **错误数字留在证据原话里** |

可以看到：
- 两组 ASR 输入下，大模型都**没有把"18 到 5 岁"写进结论**，而是改写成"目标年龄区间"。这避免了一条错误事实，但也丢掉了具体数字。
- baseline 的引文原样保留了错误数字。读者如果只看引文，会读到"十八到五岁"。
- segmented 方案因为 ASR 断句碎，把颜色待办和"主推年轻化"合并成一条，于是 `clip01-f03` 在评测里记为遗漏（上面归因表里的"ASR 导致"）。

**4. 怎么发现和纠正**：
1. 每条纪要都带证据时间段，且时间段来自转写，不由模型生成。segmented + asr 的 127.40–150.96 s 和 baseline + asr 的 142.88–150.96 s 都覆盖了原话所在的 142.72–150.87 s（评测里"原话片段覆盖"为 1/1）。
2. 审阅者从纪要点击跳转、回听这段音频，能听到"十八到五十岁"，直接把纪要改成"18–50 岁之间的色彩方案后续确认"。
3. 用人工转写跑同一流程（B 组），纪要直接得到正确数字。这就确认了错误来自识别而不是整理，属于"ASR 导致"。

**5. 结论**：数字和人名这类短词一旦识别错，大模型无法自行纠正，只能靠"证据时间段 + 回听"兜底。所以证据时间段必须来自转写本身，并且要能覆盖原话。在本例中这一点做到了。
